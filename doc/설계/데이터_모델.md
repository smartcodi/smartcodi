- `currentStep`은 단계 상태에서 **파생하지 않는** 명시 필드다. 순서를 건너뛴 자유 진행을 허용하기 때문이다(앞 단계가 미완료면 카드에 `건너뜀 n` 경고만 띄운다).
- `tasks`·`docs`의 키는 정본의 문구 그 자체다. 문구를 고치면 기존 체크가 풀린다 — `doc/단계_역할_정본.md` 6절을 따른다.

## 기관·담당자 마스터 — `accounts` · `contacts` 컬렉션

```jsonc
// accounts/{id}  기관 (소공인 업체 / 코디 소속기관 / 공급기업 / 컨설팅사)
{ "type": "sogongin|coord|supplier|consultant", "name": "", "phone": "",
  "address": "도로명", "addressDetail": "동·층·호", "visitNote": "주차·출입 안내", "memo": "", "isSample": true }
// contacts/{id}  사람 — 반드시 한 기관에 속한다
{ "accountId": "a_...", "name": "", "title": "대표", "phone": "", "email": "", "kakao": "", "memo": "", "isSample": true }
```

- 과제의 `contacts[role]`은 **스냅샷**이다. `buildMessage`·필터·보고서·일정이 전부 스냅샷(`name/email…`)을 읽는다. 스냅샷 `name` = `이름 + ' ' + 직함`이라 `addressee()`의 직함 인식이 그대로 동작한다.
- **마스터를 고치면 연결된 과제에 자동 반영한다**(사용자 결정). `saveContact`/`saveAccount` → `syncProjects()`가 `contactId`로 연결된 과제 중 값이 달라진 것만 다시 저장한다. 소공인 기관명이 바뀌면 과제 `company`도 바뀐다. **`activities`(보낸 이력)는 바꾸지 않는다.**
- 지정된 담당자는 삭제할 수 없고, 담당자가 남은 기관도 삭제할 수 없다.

## 사업계획서 점검 — `checklists/plan` · 과제 `planDocs`

```jsonc
// checklists/plan — 보드 소유자만 쓰기(db 규칙), «관리» 탭에서 편집
{ "title": "사업계획서 체크리스트", "source": "근거",
  "items": [{ "id": "ck_01", "kind": "board|ai", "boardKey": "swLimit|swPeriod|inkindTarget|inkindFill|govCap", "text": "항목", "guide": "판정 기준" }],
  "updatedAt": "ISO8601", "by": "user id" }
```

- 흐름(2026-09-28 사용자 요청): 코디네이터가 초안을 보내고 소공인이 수정본을 돌려준다 → 4단계 «사업계획서 버전 · 체크리스트 점검»에서 **PDF**를 등록(`planDocsSection`, assets 저장) → «체크리스트로 점검»(`runPlanCheck`) → 결과를 사람이 고쳐 «점검 결과 확정». 단계 상태는 바꾸지 않는다.
- **board 항목**은 보드 수치로 판정한다(`boardVerdict` — `budgetOf`·`periodSpan`·`monthsEnd`·`inkindMost`). **ai 항목**은 `sample.json` 한 번 호출로 판정한다(`planPrompt`). 프롬프트에는 판정 원칙(근거 없으면 unknown, 추측 금지, 근거 인용), 보드 사실(업체·공고·사업기간·도입 장비·계산 사업비·현물 인력), 항목(`[id:…] 항목 — 기준: …`), 문서가 들어간다.
- **문서 읽기**: pdf.js 3.11.174(cdnjs, 처음 누를 때 로드)로 텍스트를 추출한다. worker 스크립트를 일반 script로 불러 메인 스레드에서 돈다(다른 출처 Worker 불가).
  - 쪽당 평균 글자 50자 이상이면 텍스트 모드(앞 12,000자, 요청 64KiB 한도).
  - 그보다 적으면 **쪽 이미지 모드**: canvas → PNG, `sample.limits().images.maxCount`까지. 양식 원본 `03_PDF/1. 소공인 사업계획서.pdf`는 «Microsoft Print to PDF»라 텍스트가 없어 이 모드로 읽힌다.
  - 이미지도 못 보내는 화면이나 Claude를 쓸 수 없는 화면(`use('sample')` null, `not_granted` 등)이면 ai 항목을 «미확인»으로 두고 사람이 판정한다.
- **사용량·동의**: ai 판정은 버튼을 누른 사람의 Claude 사용량을 쓴다. 그 화면의 첫 호출에 동의 창이 뜬다. 자동 재시도는 하지 않는다.
- 결과에 항목 문구 스냅샷을 남기므로, 체크리스트를 고쳐도 지난 기록은 그대로다. 점검 뒤 체크리스트가 바뀌면 결과 위에 «다시 점검하세요»를 표시한다.
- 하네스는 `tests/e2e/fixtures/checklist-plan.json`(= 실제 아티팩트에 넣은 checklists/plan)을 초기화 때 넣는다. 목 `sample`은 «지원 불가» 항목만 fix로 돌려준다.

## 사업 규칙 — `programs` 컬렉션 (문서 id = 연도 `"2026"`)

```jsonc
{ "agreeDefault": "2026-09-21", "end": "2026-12-20",   // 기본 협약일(과제에 협약일이 없을 때 표시만) · 사업 종료일
  "swRate": 10, "swCap": 6000000,                       // S/W 임차비 ≤ 총 사업비 swRate% (최대 swCap원)
  "inkindRate": 20, "salaryYear": 2025,                 // 현물 목표·상한(총 사업비의 %) · 인건비 기준 연도(직전년도)
  "govRate": 60, "govCap": 36000000,                    // 국비 = 총 사업비 × govRate% (최대 govCap원). 현금 = 총 − 국비 − 현물
  "swLeftoverToHw": false,                              // 기간이 짧아 남는 S/W 예산의 H/W 전용 가능 여부
  "note": "", "source": "공고·운영지침·확인일" }
```

- **해마다 바뀌는 사업 규칙은 코드에 두지 않는다**(2026-09-28 사용자 결정 — 메타정보로 관리). 과제 연도 = 차수 앞 4자리(`programYear`), 규칙 = `programOf(p)`.
- 편집: 과제 탭 «사업 규칙 (연도별)» 카드 / 4단계 체크포인트의 «사업 규칙 보기·수정»(`openProgramForm`). 연도 변경·삭제는 넣지 않았다. 편집 권한자 누구나 고칠 수 있다.
- **규칙이 없는 연도는 «YYYY년 사업 규칙 없음»**으로 표시하고 기간·한도 경고를 내지 않는다(기본값을 지어내지 않는다).
- 2026 값의 근거: 2026년 모집 공고(98_) 본문 1.라·바·사 + 기본 협약일 9/21·남는 S/W 예산 H/W 전용 불가는 사용자 확인(2026-09-28). 추가공고(99_)는 별첨 사업비 표가 같고 본문 PDF를 판독하지 못해 같은 규칙을 적용했다(미확인). 공고 1.바 «(10% 한도의) 잔여금액은 스마트장비 구매비용으로 사용 가능»은 계획 단계의 한도 이야기로 보고, 협약 후 기간 부족으로 남는 예산은 전용 불가(`swLeftoverToHw:false`)로 둔다.
- 사업비 계산값(총 사업비·국비·현금)은 **입력값 기반 계산**이다. 보고서·과제 상세에만 보이고 사업계획서 초안 사업비 칸은 여전히 빈칸이다(원가산정보고서로 조정될 수 있음 — 공고). `govRate`가 없는 연도 규칙이면 국비·현금은 «—».
- 테스트 하네스는 `tests/e2e/fixtures/program-2026.json`(= 실제 아티팩트에 넣은 값)을 초기화 때 넣는다. 실제 값을 바꾸면 이 파일도 맞춘다.

## 장비·자산 — `products` · `assets` 컬렉션

```jsonc
// products/{id}  장비(Product)
{ "kind": "hw|sw", "name": "", "model": "", "supplierId": "a_...(공급기업 기관)", "unitPrice": 1200000 /* 숫자 또는 '' — 견적서 값만 */,
  "unit": "대|식|개|월(임차)", "spec": "", "memo": "", "isSample": true }
// assets/{id}  자산(Asset) = 장비 × 과제
{ "projectId": "p_...", "productId": "pr_...", "qty": 1, "serial": "",
  "status": "review|ordered|installed|operating",   // 검토 중 / 발주 / 설치 완료 / 가동 중 — 섞지 않는다(«성과 달성»은 장비 상태가 아니라 넣지 않음)
  "orderedAt": "YYYY-MM-DD", "installedAt": "", "operatingAt": "", "memo": "" }
```

- 공급기업·장비·과제 이름은 **id로 그때그때 찾는다**(과제 `contacts` 같은 스냅샷 없음). 설치 위치는 과제의 `visitOf`.
- 자산 상태와 단계 진행(6단계 장비 공급·7단계 가동 확인)은 **자동으로 잇지 않는다** — 둘 다 사람이 바꾼다.
- 자산이 남은 장비는 삭제할 수 없다. 과제를 삭제하면 그 과제의 자산도 함께 삭제된다.
- 양식 초안(사업계획서 H/W·S/W 목록, 3차 «④ 도입 장비», 결과보고서 4)은 자산 + 장비 마스터를 읽는다(`양식_작성.md`). 금액은 넣지 않는다.
- **사업기간 · S/W 임차 · 현물 인건비**(2026-09-28 사용자 요청 — 사업계획서 작성 때의 체크포인트). **값은 코드가 아니라 연도별 사업 규칙 `programs/{연도}`에서 읽는다**(위 «사업 규칙» 절). 규칙 식:
  - 사업기간 = 협약일(과제 `agreementDate`, 없으면 규칙의 `agreeDefault`) ~ 규칙의 `end`. S/W 임차기간은 사업기간 이내.
  - 총 사업비 = H/W + S/W + 현물. H/W·S/W는 국고+현금으로 사고(별첨 사업계획서 H/W·S/W 표), 현물은 과제책임자(대표자·기존 직원)의 직전년도 연봉으로 계상한다. 한도(원 미만 버림):
    - `S/W ≤ min((H/W + 현물) × swRate / (100 − swRate), swCap)`
    - `현물 목표 = (H/W + S/W) × inkindRate / (100 − inkindRate)`(`ratioOf`). 2026(10%·20%)이면 ÷9·÷4이다.
    - 현물은 목표를 넘으면 초과 경고를 띄운다. 모자라면 부족분만큼 현금 자부담이 늘어나므로 부족 경고를 띄운다(과제 상세는 인력을 넣었을 때만, 체크포인트는 항상).
  - 과제 상세 «도입 장비» 아래에 합계 줄(`budgetOf`·`budgetLine`)과 경고(`budgetWarnBox`)를 둔다.
  - 4단계 «사업계획서 체크포인트»(`planCheck`)가 점검하는 것:
    - 사업기간 «n개월 m일».
    - 월(임차) S/W는 `협약일 + 개월 − 1일`이 종료일을 넘으면 «최대 n개월» 경고. 끝 문장은 규칙의 `swLeftoverToHw`에 따라 «H/W 등으로 돌려 쓸 수도 없습니다» 또는 «H/W 구매비로 쓸 수 있습니다». 월 단위가 아닌 S/W는 수동 확인을 안내한다.
    - 인력별 `연봉 ÷ 12 × 계상 개월 × 참여율`. 계상 개월이 사업기간의 온전한 개월 수를 넘으면 경고한다.
    - **«직전년도 연봉 있음 — 대표자·기존 직원»(`labor[].eligible`)을 체크한 인력만 현물 합계에 넣는다**(공고 1.사). 새 행은 미체크.
    - **현물 목표를 채울 수 있는지:** 자격 있는 인력 전원을 참여율 100% × 사업기간 온전한 개월로 계상해도 목표보다 작으면 «채울 수 없습니다» 경고. 9/21 협약(3개월)이면 목표 12,750,000원에 연봉 합계 5,100만 원이 필요하다.
  - **남는 일수(예: 7/1 협약 → 5개월 20일의 20일)는 개월에 넣지 않는다.** 일할 계상 여부는 운영지침 확인 전까지 미확인. 참여율 기본값은 두지 않는다(공고에 없음). 새 인력의 계상 개월 기본값 = 온전한 개월 수.
  - 화면 표시·경고만 한다. 사업계획서 초안 사업비 칸은 여전히 빈칸이다. 추가공고(99_)는 별첨 사업비 표가 같고 본문 PDF는 판독하지 못해 같은 규칙을 적용했다(미확인).
- 단가 없는 장비(«포함» 품목)는 합계에서 빼고 이름을 밝힌다.
- 장비 단가는 쉼표가 있으면 세 자리 묶음인지 검사한다(`6,600,00` 같은 오기는 저장 거부).
- 기존 직접 입력 담당자(`contactId` 없음)는 과제 상세의 «담당자로 등록 후 연결»(`promoteLegacy`)로 옮긴다.
- 인사말: 소공인 외 역할은 기관명을 앞에 붙인다(`orgPrefix` — 이름에 기관명이 들어 있으면 생략). 직함 목록 `TITLES`에 없는 직함은 "… 님"으로 끝난다.
- **직함은 이름과 따로 관리한다**(2026-09-28 사용자 결정). 담당자 «직함» 칸은 `TITLE_LIST`(= `TITLES` 목록) 추천 + 직접 입력이고, 이름 끝 단어가 `TITLE_LIST`의 직함이면(`홍길동 대표`) 저장을 거부한다 — «대표 대표» 방지. 붙여 쓴 이름(`C1대표`)은 막지 않는다.
- 보내기 창의 «수신자 추가»(담당자 목록에서 선택 / 이메일·카톡ID 직접 입력)는 그 창에서만 쓰고 저장하지 않는다. 활동 이력 `to`에는 `role: ''`로 남는다.

- 활동 이력은 `activitiesOf(p)`로만 읽는다. `activities`와 구형 `steps[n].mails`를 합쳐 최신순으로 돌려준다. 추가는 `addActivity(id, act)` — 항상 `state.projects`의 최신 문서에 덧붙인다.
- 문서 1건 256KB, 아티팩트당 5,000건 한도. 연 20건 규모에서는 여유가 크지만, `notes`·`activities`(본문 전체 저장, 건당 1~2KB)가 무한히 쌓이는 구조이므로 한 과제가 비대해지면 오래된 메모·이력을 정리한다.

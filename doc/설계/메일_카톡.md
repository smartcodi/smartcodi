# 메일 · 카톡 보내기

> `CLAUDE.md`에서 분리한 기능 설계 문서(2026-09-29). 이 기능의 코드를 고치기 전에 읽고, 동작을 바꾸면 이 문서도 같이 고친다.

각 단계 상세의 `메일 · 카톡 보내기` 버튼이 문구 작성 모달을 연다(`openSend`). 수신자(4개 역할, **여러 명 선택 가능**) × 문구(일정 조율 / 일정 안내 / 자료 요청 / 수행일지 송부 / 서명 요청 / 완료 공유)를 고르면 `buildMessage(p, s, roles, kind)`가 제목·본문을 만들고, 사용자가 고쳐서 내보낸다.

- 수신자를 여럿 고르면 **한 통에 모두 받는 사람**으로 넣는다(사용자 결정). 인사말은 `addressee()`를 수신자마다 적용해 `, `로 잇고, 역할별 업무 목록은 수신자가 한 명일 때만 넣는다.
- 기본 수신자는 단계 주관 역할이고, 주관이 코디네이터인 단계(1·2·7·8)는 소공인이다.
- `서명 요청`은 이름에 `서명`이 든 산출물이 있는 단계에만, `수행일지 송부`는 방문 단계에만 나온다(`kindAvail`).

**메일은 «Gmail로 보내기»로 바로 발송한다.** 보는 사람의 claude.ai Gmail 커넥터를 `mcp.callTool('Gmail', 'send_message', …)`로 부른다(보내는 계정 = 그 사람의 커넥터 계정).

- 버튼을 **두 번** 눌러야 발송된다(첫 클릭은 "n명에게 발송 확인" 단계). 이메일이 없거나 형식이 틀린 수신자가 하나라도 있으면 이름을 밝히고 막는다.
- 응답에 메시지 `id`가 있을 때만 "발송했습니다"를 표시하고 `activities`에 `record:'auto'`로 기록한다. 그 외에는 절대 "보냈습니다"라고 표시하지 않는다.
- **카톡·메일 앱은 수동 기록이다.** 앱이 보낼 수도, 보냈는지 알 수도 없으므로 사람이 직접 보낸 뒤 «카톡 보냄 기록»·«메일 앱으로 보냄 기록»을 누르면 `record:'manual'`로 남는다(사용자 결정). 화면 문구는 "보냄으로 기록했습니다"이지 "발송했습니다"가 아니다. 같은 창·같은 문구로 두 번 기록되지 않는다.
- **첨부 출처 3가지**(«Gmail로 보내기» 전용, 여러 개): «내 컴퓨터» · «보드 파일»(과제 자료함 / 이 과제 Word 초안 5종 — 보낼 때 생성 / 양식 원본 PDF 4종) · «구글 드라이브»(Drive 커넥터 도구 확인 전까지 `DRIVE_TOOLS = null`이라 버튼 숨김).
- **전송 한도**(`packAttachments`): 커넥터 입력 1MiB 때문에 700KB 이하 파일은 base64로 **합계 700KB까지**, 그보다 큰 파일은 `$file`로 **호출당 1개(16MB)**. 넘치면 발송하지 않고 드라이브 링크로 안내한다. 링크 항목은 본문 끝 `[첨부 링크]`에 붙는다. 수행일지 원본 PDF(3.7MB)는 큰 파일 1개 자리를 차지한다.
- 이력을 남겨도 단계 상태는 바꾸지 않는다.
- **회신 추적**(`checkReplies`): «자료 요청»·«일정 조율» Gmail 발송(30일 이내)의 스레드를 `get_thread`(`METADATA_ONLY`)로 읽어, 보낸 메일보다 늦은 `SENT` 라벨 없는 메일이 있으면 회신으로 보고 활동에 `repliedAt`을 저장한다. 미회신은 저장하지 않고 화면에만 «n일째 미회신». 스레드 id는 **보낸 사람 메일함 기준**이라 다른 계정에서는 «확인 불가». 응답 모양 실측(2026-09-28): `{id, messages:[{id, date, internalDate, sender, labelIds, …}]}`.
- 오류는 코드별로 안내한다(`mailError`). `server_unavailable`·`upstream_error` 등은 **실제로 나갔는지 알 수 없는** 상태이므로 자동 재시도하지 않고, 보낸편지함 확인을 안내한다.
- **«수행일지 송부»** 문구(`kind: 'log'`)는 방문 단계(1·2·7·8)에만 나오고, 고르면 수신자가 소공인으로 바뀐다. **첨부가 없으면 발송을 막는다**(본문이 "첨부해 보내드립니다"이므로). 수행일지 본문은 이 보드가 만들지 않는다 — 별도 프로젝트에서 작성한 파일을 첨부할 뿐이다.
- 커넥터를 못 쓰는 화면(`use('mcp')`가 `null`)에서는 버튼을 숨기고 기존 «메일 앱 열기»(`mailto:`, 열렸는지 알 수 없음)·«본문 복사»로 돌아간다. 저장 권한이 없으면 이력을 못 남기므로 발송도 막는다.
- **카카오톡은 웹에서 임의의 상대에게 보낼 방법이 없다.** Kakao JS SDK는 CSP 허용 목록(cdnjs·jsDelivr·unpkg·cdn.tailwindcss.com·code.jquery.com)에 없어 로드 자체가 안 되고, 로드돼도 앱키·도메인 등록·OAuth가 필요하다. 그래서 문구를 만들어 복사시키는 데서 멈춘다.

`buildMessage`를 고칠 때 주의할 것:

- 줄 배열에서 **`null`은 그 줄을 빼고, `''`는 빈 줄로 남긴다**(`lay()`). 예전에 `''`를 필터로 걸러 빈 줄이 전부 사라진 적이 있다.
- 존칭은 `addressee()`를 쓴다. 이름에 이미 직함이 붙어 있으면(`정상호 대표`) `님`만 붙이고, 없으면 역할에 맞는 존칭을 붙인다. 문자열을 직접 이어붙이면 "정상호 대표 대표님"이 된다.
- 근거 없는 수치·성과를 문구에 넣지 않는다. 본문에 들어가는 값은 전부 과제 데이터에 실제로 입력된 것이어야 한다(`doc/참고/작성원칙_요약.md` 3절).

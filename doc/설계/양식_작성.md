**보드(단계 상세 «양식»)**
- «원본 PDF ↗»: `03_PDF`의 PDF를 아티팩트 `files`로 함께 게시한다(`forms/plan|log|result|cases.pdf`). **재게시 때 `files`를 생략하면 유지되고, 원본 PDF가 바뀌면 같은 경로로 다시 올린다.** `02_DOC`의 .doc는 1~12KB짜리 Word-HTML 조각이라 쓰지 않는다.
- «Word 초안 받기»: `buildDraft(form, p)` → `buildDocx` → `downloads.save(.docx)`. docx 라이브러리는 처음 누를 때 jsDelivr에서 받는다(`docx@9.7.2/dist/index.iife.js`, 전역 `docx`).
- «Claude 작성 요청 복사»: 아래 Claude 절차를 부르는 요청 문구.
- 초안 규칙(`buildDraft` · `tools/form-values.mjs` 공통 — 한쪽을 바꾸면 다른 쪽도):
  - 기초 항목 = 보드 값(업체·대표자(직함 제거)·연락처·코디·차수·일자(+요일)·방문지·공급기업·다음 방문 단계). 보드에 없는 값(사업자등록번호·수행시간·투입시간·면담 여부·사업비 금액)은 **빈칸**.
  - 본문 = 관련 단계 메모 `· (MM-DD) 원문` + 완료 체크 업무 `· [완료] …` + 연락 이력, 끝에 `[보드 메모 기반 초안 — 검토 후 다듬을 것]`. 근거가 없으면 `미확인 — <양식 안내문>`.
  - 현장진단표 항목(`DIAG` 행)은 방문 단계 상세의 «현장진단표 항목» 입력값(`steps[1|2|7].diag[항목명]`, 1·2·3차)을 그대로 넣고, 비어 있으면 `미확인 — <안내문>`. 결과보고서 1~6은 관련 진단 입력(`diagLines`, 매핑은 `buildDraft` 주석) + 단계 메모를 합친다. 그 밖의 예외: 2차 «이전 코디네이팅 요약» = 1단계 메모, 3차 «① 이전 요약» = 1·2단계 메모, «④ 도입 장비» = 공급기업 + 자산 줄 + 3·6단계 메모, «제출 완료 여부» = 4단계 완료일.
  - **자산 → 초안**(2026-09-28 사용자 결정): 이름·모델·단위·공급기업은 자산의 `productId`로 장비 마스터에서 읽는다(`assetLines`·`assetSuppliers`). 사업계획서 H/W·S/W 목록 = `· 장비명 모델 × 수량단위`, H/W·S/W 공급기업 = 그 구분 자산의 공급기업(없으면 과제 공급기업 담당자). 3차 «④»·결과보고서 4 = `· [H/W] 장비명 모델 × 수량단위 — 공급기업 (자산 상태)`. **금액은 넣지 않는다**(사업비 칸은 빈칸 유지).
  - **수치를 새로 만들지 않는다**(메모 원문 수치만). 메모 날짜는 한국 시간 기준이다.

**Claude Code 절차 — 제출용 .hwpx**
1. `forms/`에 해당 양식의 **.hwpx 원본**이 있는지 확인한다. 없으면 멈추고 "한글에서 다른 이름으로 저장 → HWPX로 저장해 forms/에 넣어 달라"고 안내한다. **.hwp를 kordoc으로 직접 채우지 않는다** — 2026-09-28 실측에서 hwpx로 재생성되며 표 칸이 빠지고(진단표 값 열 소실), 배열 값이 라벨 칸을 덮어썼다(`사업자등록번호` → 업체명). 이 PC에는 한컴오피스·LibreOffice가 없어 자동 변환도 안 된다.
2. `ArtifactData get projects/<id>`, `list accounts`·`list products`·`list assets`를 `out_dir`로 `output/_data/`에 받는다(스크래치패드 경로는 저장 규칙에 막힌다). 컬렉션마다 `{id: data}` 한 파일로 합친다.
3. `npx -y kordoc@^4 fill forms/<원본>.hwpx --dry-run > fields.json` → `node tools/form-values.mjs <formId> <project.json> fields.json accounts.json [products.json assets.json <projectId>] > values.json`(뒤 셋은 사업계획서 H/W·S/W 공급기업용. `공급\n기업` 칸 0번 = H/W, 1번 = S/W로 가정 — .hwpx dry-run에서 확인).
   - **.hwpx 원본으로 처음 돌릴 때는 dry-run 순서·블록 구분(수행일지: 블록 시작 = 신청인 칸 앞 `업체명`)을 다시 확인한다**(.hwp 기준으로만 확인됨, 미검증).
4. 본문 칸은 values.json에서 메모·활동만 근거로 문장을 다듬는다. 없는 값은 '미확인'.
5. `npx -y kordoc@^4 fill forms/<원본>.hwpx -j values.json -o output/<업체>_<cycle>/<양식>_<YYYYMMDD>.hwpx` → `validate` 통과 확인 → `kordoc`으로 다시 읽어 **대상 차수 표에만 값이 들어가고 다른 차수·작성 예제·라벨 칸은 그대로인지** 확인한다.
6. fill이 인식하지 못하는 칸(진단표 ①~⑧, 결과보고서 1·3~6 등)은 project.json의 `steps[n].diag` 입력값·메모와 자산(사업계획서 H/W·S/W 목록, 3차 «④», 결과보고서 4 — 보드 «Word 초안»과 같은 줄)으로 `kordoc <out>.hwpx -o edit.md` → 편집 → `kordoc patch <out>.hwpx edit.md -o <최종>.hwpx`.
7. `render --reflow`로 미리보기를 확인하고 사용자에게 경로를 알린다.

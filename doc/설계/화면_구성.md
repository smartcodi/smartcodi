| (보드 도우미) | 상단 «💬 도우미»로 여닫는 오른쪽 대화창(휴대폰은 전체 화면). **버튼은 claude.ai 안이면 항상 보이고**, 못 쓰는 화면이면 창이 이유를 먼저 알린다(`assistCaps` — Claude 불가면 보내기 꺼짐, 사진 불가면 «📎» 숨기고 텍스트로 안내). **실측(2026-09-29): claude.ai 웹(Chrome)은 `sample`은 되지만 사진을 못 보낸다(`limits().images` 없음) — 웹에서는 명함 텍스트만 가능.** 사진이 되는 앱(휴대폰 등)은 미확인. 명함 사진을 **붙여 넣기(Ctrl+V)·끌어 놓기·📎 첨부**하고 «등록해 줘»처럼 말한다. 매 턴 `sample.json` 한 번(turns = 규칙 턴 + 최근 12턴 + 이번 말·[현재 명함])으로 `{reply, card, action}`을 받는다. card는 말풍선의 `cardReview`로 보이고, «유형은 공급기업이야»처럼 대화로 고친다. action `register`면 마지막 카드의 «등록 창 열기»와 같이 미리 채운 창을 연다(저장은 사람). 규칙 턴에 보드의 기존 기관 목록(최대 150)·과제 목록(최대 100)·양식 목록·지금 열린 과제를 넣는다. **양식 초안**(2026-09-29): «대한정밀 2차 수행일지 써 줘. 오늘 방문에서 … 논의함» → action `draft`(projectId·formId; 과제는 업체명 → 열린 과제 → 되묻기) → `assistDraft`가 `buildDraft` 뼈대(보드 값)를 만들고 `미확인 — …`·초안 표시 칸만 «[작성]» `sample.json` 한 번으로 채운다(근거 = `evidence`·진단 입력·도입 장비 + 이번 대화의 사용자 말, 근거 밖 사실·수치 금지, 없으면 `미확인 — 안내`, 쓴 칸에 `[도우미 작성 초안 — …]`). 미리보기 말풍선에서 «Word로 받기» / «N단계 산출물로 등록»(`registerOutput` → `steps[n].outputs` 버전 vN, **산출물 체크는 건드리지 않음**) / «알려 준 내용을 단계 메모로 저장». 단계 상세 산출물 아래 «산출물 초안» 목록(`outputsEl` — Word로 받기·보기·삭제). **견적서 등록**(2026-09-29): «📎 첨부»(PDF는 사진 불가 화면에서도 보임)로 견적서 PDF → `readPdf`로 글자를 뽑아 `[견적서 PDF: 파일명]` 블록으로 보냄(앞 `QUOTE_TEXT_MAX` 8,000자, 스캔본은 사진 가능 화면에서만 쪽 이미지) → 답의 `quote`를 `normQuote` → 말풍선 `quoteReview` 표: 공급기업(이름 일치 자동, «+ 새 공급기업으로 등록…» → `openAccountForm`)·과제(`projectId` → 열린 과제, «과제 없음 — 장비만»)·품목별 구분·수량·단위 확인 → «선택한 N건 등록»(사람이 누름)이 새 장비 `saveProduct`(견적 단가·견적번호 메모) + 자산 `saveAsset`(status `review`). 같은 공급기업·같은 모델(모델 없으면 같은 이름)이면 기존 장비를 쓰고(`quoteMatch`, 구분·단위는 기존 값), 기존 단가는 «단가 갱신» 체크 때만 바꾼다(다른 과제 사업비도 바뀜). 그 과제에 이미 자산이 있는 품목은 선택 해제로 시작. «등록해 줘»라고 해도 자동 저장하지 않고 표의 버튼을 안내한다. 명함·견적서 등록, 양식 작성 외 요청은 못 한다고 답한다. 대화·이미지·PDF는 화면 메모리에만 있고(저장 안 함), 첨부는 그 턴에만 보낸다. 누른 사람의 Claude 사용량을 쓴다(API 키 불필요 — claude.ai 안에서만 동작) |
| (명함으로 등록) | 기관·담당자 탭 머리 버튼(`openCardImport`, `sample` 없으면 숨김). 명함 **텍스트나 사진**(여러 장, `limits().images`일 때) → `sample.json` 한 번 → 미리보기 → «등록 창 열기»로 `openAccountForm`(유형·이름·대표전화·주소·상세·메모 미리 채움) → 저장하면 `openContactForm`(이름·직함·휴대폰·이메일 미리 채움) → 사람이 저장. 같은 이름 기관이 있으면 «기존 기관에 담당자 추가»가 기본, 같은 이메일·휴대폰 담당자가 있으면 경고. 원칙: 명함에 적힌 값만(추측 금지), 이름 끝 직함은 나눔, 저장은 사람, 사진은 저장 안 함, 누른 사람의 Claude 사용량 |

| 보고서 → 실적·진행·사업비 | 기간별 방문 실적 + 기업별 진행 현황 + **사업비 현황**(`budgetCard` — 과제별 H/W·S/W·현물·총 사업비·국비·현금 계산값과 점검 배지, 합계 행). CSV 내보내기, 요약 복사 |

**상세 패널(오른쪽)은 한 번에 하나**이고, 목록 행을 누르면 열린다. 과제 = `state.openId`, 기관·담당자 = `state.rec`. 상세끼리는 `go(t, id)`로 오가며 이전 상세가 `state.back`에 쌓여 «← 뒤로»로 돌아간다. 닫으면(`closeRec`) 스택이 비워진다.
- 과제 상세: «기관 보기»(소공인 기관), 역할별 담당자의 기관명·이름 링크
- 기관 상세: 기관 정보 · 담당자(→ 담당자 상세) · 관련 과제(→ 과제 상세) · 연락 이력
- 담당자 상세: 소속 기관 링크 · 연락처 · 참여 과제(역할 표시) · 연락 이력
- 과제 상세 «도입 장비»(자산 목록 + «장비 도입 등록»), 공급기업 기관 상세 «공급 장비», 소공인 기관 상세 «도입 장비». 휴대폰 «더보기»에 장비·자산 포함
- 연락 이력 매칭(`sentTo`): 활동 `to`의 `contactId`, 없으면 현재 이메일·카톡ID와 주소 일치. 기관 상세는 `to.org` 또는 이름이 기관명과 같은 수신자도 포함한다. **연락처나 기관명을 바꾸면 그 전 주소·이름으로 보낸 (contactId 없는) 기록은 더 이상 매칭되지 않는다.**


## 주요 함수 (인수인계 2026-09-29에서 옮김 — 코드에 있음 확인)

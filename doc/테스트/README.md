## 공통 규칙

1. **테스트 데이터 표시** — 업체·기관·담당자·장비 이름 앞에 반드시 `[테스트]`를 붙인다. 사례 PDF에는 업체명이 없고, 실제 업체로 오인될 이름을 만들지 않는다(CLAUDE.md «절대 하지 말 것»). 장비 모델명·단가는 PDF 원문 그대로 쓴다.
   - 공급사: PDF에 공급사 이름이 적힌 곳은 CASE1(비고란)뿐이다. 테스트에서는 실제 회사명을 기관으로 등록하지 않고 `[테스트] CASE1 공급사`처럼 쓴다.
2. **수치는 PDF에 있는 것만** — 매출은 "2억 이상/미만"까지만 알 수 있다. 정확한 매출액·사업자등록번호·주소는 PDF에 없으므로 **비워 둔다**. 초안에 이 값들이 나타나면 결함이다.
3. **메일 수신자** — 담당자 이메일은 테스트용 보조 계정으로 넣는다(자동 테스트는 `tester@example.com` — 목 발송이라 실제로 나가지 않음. 실제 보조 계정 주소는 로컬 `CLAUDE.local.md`). 실제 외부 주소를 넣지 않는다. 발송 계정은 보는 사람의 Gmail 커넥터 계정(업무용 구글 계정)이다.
4. **날짜** — 시나리오의 날짜는 실행일 `T` 기준 상대값(`T-3`, `T+5`)으로 적었다. 입력할 때 실제 날짜로 바꾼다.
5. **정리** — 각 시나리오 끝의 «정리» 절차 또는 CASE6의 일괄 정리를 반드시 수행한다. 정리 전에 «전체 백업»을 받아 두면 결과 증거로 쓸 수 있다.

## 공통 사전 조건

- 보드를 **편집 권한 계정**(보드 소유자 계정 로그인)으로 연다. 처음 열 때 뜨는 권한 요청(Gmail·Google Calendar·사용자 정보)은 허용한다.
- Gmail·Google Calendar 커넥터가 업무용 구글 계정에 연결돼 있다(CLAUDE.md «계정»).
- 데스크톱 브라우저 창 폭 1200px 이상. 휴대폰 항목은 실기기(또는 개발자도구 기기 모드 390px)로 따로 본다.

## 판정 기준

- 각 단계의 «기대 결과»가 모두 맞으면 **통과**.
- 다음은 기능이 맞아도 **결함**으로 기록한다: 입력하지 않은 값이 초안·메일·보고서에 나타남 / 추가공고 과제가 원공고로 보임 / "발송했습니다"가 실제 발송 없이 표시됨 / 상태가 사람 조작 없이 «완료»로 바뀜.
- «보드 밖 확인»(S/W 한도 계산 등)은 보드가 계산하지 않는 항목이다. 시험자가 계산해 메모로 남기고, 결과를 «기능 공백» 칸에 적는다.

## S/W 한도 — 보드 밖 확인 요약

CLAUDE.md에 적힌 규칙 `S/W 한도 = min(H/W ÷ 9, 600만원)` 기준(원문 `doc/참고/작성원칙_요약.md`는 이 폴더에 없어 **미확인**). 금액은 PDF의 공급가(VAT 별도).

| 사례 | H/W 합계 | 한도 = min(H/W÷9, 6,000,000) | S/W | 판정 |
|---|---:|---:|---:|---|
| CASE1 | 45,000,000 | 5,000,000 | 3,000,000 | 한도 이내 |
| CASE2 | 42,000,000 | 4,666,666 | 9,000,000 (1,500,000 × 6개월) | **초과 4,333,334** |
| CASE3 | 42,000,000 | 4,666,666 | 6,000,000 | **초과 1,333,334** |
| CASE4 | 42,000,000 | 4,666,666 | 6,000,000 | **초과 1,333,334** |
| CASE5 | 37,000,000 (RIP 포함) | 4,111,111 | 5,286,000 (할인 후) | **초과 1,174,889** |
| CASE6 | 42,383,000 | 4,709,222 | 6,000,000 | **초과 1,290,778** |

한도는 원 단위 미만을 버렸다. **2026-09-28 공고 원문 확인**: 임차비 한도는 «총 사업비의 10%(최대 600만원)»이고 총 사업비 = H/W + S/W + 현물(인건비)이다. 위 표는 현물 0원 기준이며, 현물을 넣으면 한도가 `(H/W + 현물) ÷ 9`로 커진다. 보드는 이제 이 계산을 한다(과제 상세·4단계 «사업계획서 체크포인트», C2-14~16). 비율·상한·기간 값은 코드가 아니라 연도별 사업 규칙 문서 `programs/{연도}`에서 읽는다(하네스는 `tests/e2e/fixtures/program-2026.json`을 넣는다). 6건 중 5건이 초과 — 사례가 이 판단을 연습하도록 만들어진 것으로 보이나 교재 의도는 미확인이다.

## 실행 기록 양식

각 시나리오 파일 맨 끝의 «실행 기록» 표에 실행일·버전·결과(통과/결함/차단)·비고를 적는다. 결함은 단계 번호와 화면 문구를 그대로 적는다.
